# Практика 3: локальный помощник — отчёт

## Железо и ОС

- CPU i9-12900HK, 32 ГБ RAM, только встроенная Intel Iris Xe; инференс на CPU (`100% CPU`, раннер `llamacpp`).
- Windows 11 Pro (сборка 26200). Команды выполнялись в Git Bash из `practices/practice_03/lab` (см. «Отклонения»).

## Версии

- `ollama 0.40.2`, `opencode v2.0.20`, `Python 3.14.3`.
- Базовая модель: `qwen3.5:4b` (`d8b0f5e9760c`): 4.2B параметров, квантизация `Q4_K_M`, нативный контекст 262144, thinking по умолчанию включён.
- `itmo-agent:latest` (`bc59ed397316`, 3.3 ГБ): агентская сборка для OpenCode.
- `itmo:latest` (`78ff56478b76`, 3.3 ГБ): сборка для прямых запросов (Modelfile с усиленным SYSTEM + `seed 42`).

## Длина контекста (три места)

- Максимум из карточки модели: `qwen3.5:4b` заявляет `context length 262144` (`ollama show`).
- Сервер: `lab/Modelfile.agent` — `PARAMETER num_ctx 32768` (сборка `itmo-agent`).
- Клиент: `lab/demo/opencode.json` — `limit.context 32768` (`output 4096`), имя `ITMO local 32k`.
- Подтверждение, что сервер действительно выделил 32768: `ollama ps` показывал `CONTEXT 32768` (до смены — `65536`).
- Отдельно `lab/Modelfile` (модель `itmo` для прямых запросов): `num_ctx 4096`, `temperature 0.2`, `seed 42`.

## Ресурсы и скорость

- Контекст 65536: `SIZE 5.6 GB`, ответ «ГОТОВ» за `10м37с`. Контекст 32768: `SIZE 4.2 GB`, «ГОТОВ» за `14м57с` (память меньше, время — variance холодного старта; выводов «меньше = быстрее» не делаем). Подробности — `lab/results/resources.md`, времена — `lab/results/times.txt`.
- Прямые запросы (`experiment.py`, `think=false`, короткий контекст): `baseline.json` — `wall 31.0с / total 28.9с / 9.7 т/с`; `system.json` — `wall 12.3с / total 10.2с / 9.2 т/с`.
- Напрямую в Ollama (`Say READY`): с размышлениями ~30с (поле `reasoning` ~900 символов, ~200 completion-токенов), с `reasoning_effort:none` ~0.8с (2 токена).
- Через OpenCode (`local-guide`, `itmo-agent`): Q1–Q5 заняли 8.5–29 мин; по `step_finish` ~90–210 output-токенов на шаг при ~40 видимых — модель думает скрыто (`reasoning: 0` в логе, размышления посчитаны в `completion_tokens`).

## Сравнение конфигураций

- (а) baseline vs system: обе НЕ выдумали CI (обе честно сказали, что сведений нет), но system короче (2 абзаца против списка советов проверять `.github/workflows` и т.д.) и примерно в 3 раза быстрее (10.2с против 28.9с). Разница в форме ответа, а не в правдивости.
- (б) контекст 65536 vs 32768: память 5.6 vs 4.2 ГБ; время 10м37с vs 14м57с (variance, не эффект).
- (в) размышления: напрямую ~30с с ними / 0.8с без; в OpenCode ~200 output-токенов на шаг при ~40 видимых. Опыт отключения (п. «Эксперимент» в `resources.md`): `options.reasoningEffort:none` — 5м44с, но ответ-обрубок без команды; `body.reasoning_effort:none` — 11м53с, зато источники верные. Оставлена конфигурация по умолчанию (размышления включены): ни один вариант не дал ускорения и качества одновременно.
- (г) проверка итоговой конфигурации (`subscribe(' Ann ')`, эталон `{"subscribed": True}` + `strip()` → `"Ann"`): было 13м44с без ответа (лимит 8 шагов, уход в родительские папки); стало 9м22с с верным ответом (`service.py:7`) после `steps: 12` и границы поиска в `repo-system.txt`. Правки оставлены.

## Изоляция

- Эталоны готовил рабочий агент по коду `demo/` и держал у себя; в тестовые сессии не передавались ни эталоны, ни отчёт, ни переписка.
- Проверено по jsonl: Q1–Q5 не содержат `results`, `эталон`, `report.md`, `baseline`, `system.json`, `questions.md`; все чтения — внутри `lab/demo`.
- Исключение: `demo_check.jsonl` (проверка итоговой конфигурации, без ответа — см. ниже) выходил за `demo/` (читал каталоги `practice_03`, `lab`; `grep` зацепил сниппеты `results/q*.jsonl`). Q1–Q5 чистые.

## Правка Modelfile (эффект «до и после»)

- Причина: Q1 перепутал источники, поэтому SYSTEM `itmo` усилен: `seed 42`, явное правило про ложную предпосылку, требование файла+строки на каждый факт.
- Проверка (`README.md`+`service.py` с `cat -n`, вопрос про строку `unsubscribe`, `ollama run itmo --think=false`): до — 17.5с (`results/premise_before.txt`), после (`ollama create itmo -f Modelfile`) — 8.1с (`results/premise_after.txt`); оба ответа корректно отказывают (есть только `subscribe`). Формулировка поведение не сломала.
- Наблюдение: даже после правила «для каждого факта укажи файл и номер строки» модель номеров строк не указала (ответ «после» вообще без ссылок). Системный промпт задаёт правила, но 4B-модель выполняет их не всегда.

## Обоснование выбора

- `qwen3.5:4b` (Q4_K_M): влезает в 32 ГБ RAM на CPU (3.3 ГБ веса, 4–6 ГБ с контекстом), умеет tool-calling и русскоязычные короткие ответы. Про меньшие модели (например, 2B) — лишь предположение, что они рискуют качеством ссылок на код: мы их не проверяли.
- Контекст 32768 для агента: 65536 ел 5.6 ГБ и не давал выигрыша на репо из 6 файлов; 32768 (4.2 ГБ) с запасом покрывает `demo/` + историю шагов.
- Итоговая конфигурация: размышления включены (в единственном опытном прогоне с отключением модель оборвала планирование — наблюдение по одному запуску, см. «Эксперимент» в `resources.md`), `temperature 0.2` + `seed 42` для воспроизводимости, read-only агент (`read/glob/grep`, остальное `deny`).

## Проблемы

- VseLLM недоступен (см. «Отклонения»).
- Ответ через OpenCode занимает 8–29 минут на CPU — long-think + tool-циклы, не баг.
- Q2 завис на 20 мин (только `step_start`, раннер в `Stopping`): причина — прерванные по таймауту прогоны продолжали работать в фоне и забивали очередь Ollama. Решение: перезапуск Ollama + `opencode service set disabled true` (у каждого `run` свой сервер).
- `demo_check` (новый вопрос `subscribe(' Ann ')`): 13м44с, 7 tool-вызовов, но текста ответа нет (лимит шагов) — зафиксировано честно.
- `demo_check2` (тот же вопрос, `steps: 12` + граница поиска): 9м22с, ответ верен (`{"subscribed": True}`, `strip()` → `"Ann"`, `service.py:7`); попытка `execute` отклонена правами. Конфигурация оставлена.

## Как воспроизвести

1. `ollama pull qwen3.5:4b`; из `lab/`: `ollama create itmo -f Modelfile` и `ollama create itmo-agent -f Modelfile.agent`.
2. `make test` из `lab/` (3 теста `demo/`, только стандартная библиотека).
3. Из `lab/demo/`: `opencode run --agent local-guide --model ollama/itmo-agent --format json "<вопрос>" > ../results/qN.jsonl` — по одному вопросу на сессию, эталоны не передавать.

## Отклонения

- Рабочий агент — бесплатная модель OpenCode `opencode/muse-spark-1.3-contributor-free` (Muse Spark 1.3 Free), потому что модели VseLLM были недоступны.
- Команды выполнялись в Git Bash вместо WSL.
- Эталоны агента я проверил по коду вручную (совпали).

## Мои выводы

0. Железо для такой работы слабовато — похоже, пора копить на видеокарту.
1. Локальная 4B-модель на CPU работает, но медленно: в простом чате ответ за 10–30 секунд, через OpenCode — 8–29 минут на вопрос. Вероятные причины: каждый шаг агента — это новый запрос к модели, плюс скрытые размышления (около 200 токенов на шаг при примерно 40 видимых).
2. Системный промпт меняет форму ответа, но не его правдивость: без него модель тоже не выдумала CI, однако с ним ответила коротко и в 3 раза быстрее.
3. С инструментами чтения модель отвечает по факту: 4 из 5 верно, обе ловушки пройдены, перед ответом всегда читала файлы. Но слабое место — ссылки на источники: даже после правила «указывай файл и строку» номера строк она не дала. Ответы маленькой модели нужно проверять.
4. Контекст задаётся в нескольких местах, и сервер с клиентом должны совпадать. Переход 64k → 32k сэкономил 1,4 ГБ памяти, но работу вообще не ускорил.
5. Проблемы агента лечатся конфигурацией: после лимита 12 шагов и границы поиска в промпте проверочный вопрос получил верный ответ за 9 минут вместо обрыва за 14. А попытку запустить код остановили права: промпт говорит, как отвечать, а права решают, что можно делать.
6. Отключить размышления так, чтобы было и быстро, и правильно, не получилось: это компромисс скорость/качество.
7. Локальная модель оправдана для приватных данных и офлайна, но для агентной работы на CPU непрактична: нужна видеокарта или облачная модель. Подводный камень: прерванные прогоны продолжали работать в фоне и забивали очередь Ollama.
