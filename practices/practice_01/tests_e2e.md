# E2E-проверки

| Сценарий пользователя | Предусловия | Действие | Наблюдаемый результат | Подтверждение |
|---|---|---|---|---|
| Позитивный | Открыт PR с валидным diff, LLM доступен | Автор открывает PR, система вызывает `POST /api/reviews` | Ревьюер получает отчёт: `summary`, ≤ 3 риска (`file`, `line`, `evidence`, `risk`), `checks`; время до первого комментария ≤ 1 ч | Ручной прогон на `TRAINING_PR.diff` |
| Негативный — пустой diff | PR открыт, diff пустой | POST `/api/reviews` с `{"diff": ""}` | HTTP 400, риски не формируются, ревьюер закрывает PR без ошибок | Ручной прогон + pytest |
| Негативный — нет поля diff | PR открыт, тело запроса без `diff` | POST `/api/reviews` с `{}` | HTTP 422, ревьюер видит понятное сообщение, сервис не падает | Ручной прогон + pytest |
| Граничный — diff сверх лимита (`API-1`) | PR с diff 20 001 символ | POST `/api/reviews` | HTTP 413, LLM не вызывается, ревьюер просит разбить PR | Ручной прогон на синтетическом diff |
| Граничный — diff ровно 20 000 символов | PR с diff 20 000 символов | POST `/api/reviews` | HTTP 200, отчёт формируется | Ручной прогон + pytest |
| Отказ LLM по таймауту (`REL-1`) | Мок LLM с задержкой 15 с | POST `/api/reviews` | Timeout 10 с, контролируемый ответ, ревьюер продолжает вручную | Ручной прогон с мок LLM |
| Отказ LLM по ошибке (`REL-1`) | Мок LLM бросает `RuntimeError` | POST `/api/reviews` | Контролируемый ответ, не 500, ревьюер продолжает вручную | Ручной прогон с мок LLM |
| Проверка `SEC-1` | diff содержит тестовый token `sk-...` | POST `/api/reviews` | В prompt, отправленном в LLM, значение заменено на `[REDACTED]`; токен не уходит провайдеру | Ручной прогон с перехватом prompt |
| Проверка `OBS-1` | Включён лог-сборщик | POST `/api/reviews` с секретом в diff | В логе только `request_id`, длительность, статус; содержимого diff и ответа модели нет | Ручной прогон + grep по логам |
| Воспроизводимость | Отчёт получен | Сравнить отчёт с `TRAINING_PR.diff` и `CASE.md` | Каждый риск подтверждён строкой diff или правилом (`QA-1`); проверки воспроизводимы | Сверка вручную ревьюером |

## Как использовали AI

- Строка в `prompts.md`: P1-02.
- Что проверил студент: сценарии «diff сверх лимита» (`API-1`), «Отказ LLM по таймауту» и «Отказ LLM по ошибке» (`REL-1`), «Проверка `SEC-1`» и «Проверка `OBS-1`» добавлены после сверки с `CASE.md`; позитивный сценарий и «Нет поля diff» — из рисков P1-02 и `TRAINING_PR.diff`.
