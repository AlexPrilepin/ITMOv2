## P1-01. Baseline: только diff

**Модель:** vse-llm/gpt-4o. Отдельный временный каталог, доступ к инструментам закрыт, вход — только `TRAINING_PR.diff` и короткий запрос.

**Запрос:**

```text
Ниже diff учебного PR. Посмотри PR и найди проблемы.
```

**Ответ модели:**

```text
Проблемы в PR:

1. Метод generate в протоколе LLM определён как ... без реализации — это заглушка.

2. ReviewService.review формирует промпт простой f-строкой, без правил и формата. Модель может вернуть что угодно.

3. Ответ возвращается как {"comment": answer} без структуры. Нет summary, risks, checks.

4. В create_review нет проверки, что поле diff присутствует. Если клиент пришлёт пустое тело — будет KeyError.

5. Нет обработки ошибок LLM. Если провайдер вернёт ошибку, сервис упадёт с 500.

6. Промпт содержит всю diff без ограничений по размеру — большой PR может не влезть в контекст.

7. Нет тестов.
```

**Слабые места ответа:**

1. Нет ссылок на `file:line` — риски нельзя проверить по diff.
2. Нет evidence и шагов воспроизведения проверки.
3. Нарушено будущее ограничение `OUT-1` (≤ 3 риска) — модель вернула 7 замечаний.
4. Пункт 1 — не проблема (Protocol действительно так пишется).
5. Пункт 7 не относится к PR.

**Какой информации не хватило:** правил репозитория (`SEC-1`, `API-1`, `REL-1`, `OUT-1`, `SCOPE-1`, `QA-1`, `OBS-1`), формата отчёта, ограничения «не более трёх рисков» и понятия evidence.

## P1-02. Master prompt

**Модель:** vse-llm/gpt-4o. Тот же вход `TRAINING_PR.diff`, но передан Master Prompt v1 с Context Pack. История P1-01 не передавалась.

**Ответ модели:**

```markdown
## Краткое описание

В `app/review_service.py` добавлена реализация `ReviewService.review`, которая формирует промпт из diff и вызывает `LLM.generate`. В `app/api.py` добавлен эндпоинт `POST /api/reviews`, вызывающий `review_service.review(payload["diff"])`.

## Риски

1. `app/review_service.py`, `review`, строка с `prompt = f"Review this pull request..."` — diff отправляется во внешний LLM без удаления секретов, токенов и приватных ключей. Нарушено правило `SEC-1`.
   Evidence: в diff строка `prompt = f"Review this pull request and find problems:\n{diff}"` без предварительной санитизации.
   Проверка: передать diff с тестовым token и убедиться, что в prompt осталось `[REDACTED]`.

2. `app/review_service.py`, `ReviewService.review` — возвращает `{"comment": answer}` без структуры `summary` / `risks` / `checks`. Нарушено правило `OUT-1`.
   Evidence: в diff возвращается словарь с одним ключом `comment`; ключей `summary`, `risks`, `checks` нет.
   Проверка: отправить diff и проверить, что ответ содержит `summary`, `risks` (≤ 3), `checks`.

3. `app/review_service.py`, `review` — нет timeout на вызов LLM. Нарушено правило `REL-1` (timeout 10 с; ошибка → контролируемый ответ).
   Evidence: в diff вызов `self.llm.generate(prompt)` без `timeout` и без `try/except`.
   Проверка: подменить LLM на мок, бросающий `TimeoutError`, и посмотреть ответ сервиса.

## Проверки

- Unit: `test_review_strips_secrets` — SEC-1, prompt без токена.
- Unit: `test_review_returns_structured_report` — OUT-1, есть `summary`, `risks`, `checks`.
- Integration: мок LLM с `TimeoutError` → контролируемый ответ, не 500 (REL-1).
- Integration: diff > 20 000 символов → HTTP 413 (API-1).
- E2E: прогон на `TRAINING_PR.diff` — отчёт воспроизводим.

## Ограничения

Решение принимает человек. Помощник не выполняет approve, merge и не изменяет код и не действует в GitHub (`SCOPE-1`). Логи содержат только `request_id`, длительность и статус (`OBS-1`).
```

**Оценка:**

- Формат соблюдён: описание, ровно 3 риска, проверки, ограничения.
- Каждый риск подтверждён `file:line`, evidence и правилом из Context Pack.
- Соблюдено ограничение «не более трёх рисков» (`OUT-1`).
- Проверки воспроизводимы и ссылаются на правила.
- Соблюдены границы `SCOPE-1`, `OBS-1`.

## Master Prompt v1

### 1. Цель и роль

- Цель: получить структурированный отчёт по diff PR.
- Роль AI: помощник ревьюера. Не принимает решений, только предлагает риски с доказательствами.

### 2. Входы и источники

- Обязательный вход: `TRAINING_PR.diff`.
- Разрешённые источники: только diff и Context Pack ниже.
- Context Pack:
  - Правила: `SEC-1`, `API-1`, `REL-1`, `OUT-1`, `SCOPE-1`, `QA-1`, `OBS-1`.
  - Формат риска: `{file, line, evidence, risk}`.
  - Хороший пример: `app/review_service.py:16` — diff отправляется во внешний LLM без удаления секретов, нарушено `SEC-1`. Проверка: передать diff с тестовым token и убедиться, что в prompt осталось `[REDACTED]`.
  - Плохой пример: «Код можно улучшить. Добавьте тесты».
  - Ограничения: не approve, не merge, не менять код, не действовать в GitHub, не логировать содержимое diff и ответ модели.

### 3. Задача и артефакты

- Что сделать: найти в diff до трёх подтверждённых рисков.
- Что вернуть: краткое описание, ≤ 3 риска, список проверок.

### 4. Формат результата

- Структура: `## Краткое описание`, `## Риски`, `## Проверки`, `## Ограничения`.
- Ограничения объёма: ≤ 3 риска; каждый риск ≤ 4 строки.

### 5. Полномочия и запреты

- Разрешено: анализировать diff, ссылаться на строки, предлагать проверки.
- Запрещено: approve, merge, менять код, действовать в GitHub, выдумывать правила или строки, логировать содержимое diff.

### 6. Рабочий процесс и остановка

- Шаги: 1) прочитать diff; 2) выписать кандидатов в риски; 3) для каждого найти `file:line`, evidence и правило; 4) удалить без подтверждения (`QA-1`); 5) остановиться после 3 рисков.
- Остановка и запрос человека: если правил из Context Pack не хватает для оценки кандидата — остановиться и пометить «требует уточнения».

### 7. Проверки и подтверждения

- Как проверять утверждения: каждый риск обязан иметь `file:line`, evidence из diff и ссылку на правило (`QA-1`).
- Что сохранить: список воспроизводимых проверок.

### 8. Definition of Done

- Задача закончена, когда отчёт содержит описание, ≤ 3 подтверждённых риска и воспроизводимые проверки.
