## Context Pack для первого рабочего сценария

### Факты и правила

Правила репозитория, влияющие на этот PR:

- `SEC-1`: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи.
- `API-1`: diff длиннее 20 000 символов отклоняется с HTTP 413.
- `REL-1`: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ.
- `OUT-1`: ответ содержит `summary`, массив `risks` и массив `checks`. В `risks` максимум три элемента с полями `file`, `line`, `evidence`, `risk`.
- `SCOPE-1`: сервис только советует; он не пишет код и не выполняет действия в GitHub.
- `QA-1`: риск включается в ответ, только если он подтверждён строкой diff или правилом репозитория.
- `OBS-1`: в лог пишутся только `request_id`, длительность и статус. Содержимое diff и ответа модели не логируется.

Правила, которые не относятся к этому PR (в Context Pack не входят):

- таблицы базы данных называются в `snake_case`;
- все frontend-строки проходят через i18n.

Задача помощника:

- получает diff и возвращает краткое описание, не более трёх рисков с файлом, строкой и доказательством, список проверок;
- решение всегда принимает человек;
- помощник не может approve, merge или менять код.

### Формат входа и результата

- Вход: `TRAINING_PR.diff` (текст).
- Результат: Markdown-отчёт с разделами `## Краткое описание`, `## Риски`, `## Проверки`, `## Ограничения`. Внутри `## Риски` — ≤ 3 элемента с полями `file`, `line`, `evidence`, `risk` (`OUT-1`).

### Ограничения и запрещённые действия

- Нельзя approve, merge, менять код, действовать в GitHub.
- Нельзя выдумывать строки и правила, которых нет в diff или Context Pack.
- Нельзя возвращать больше трёх рисков.
- Нельзя логировать содержимое diff и ответ модели.

### Хороший пример

`app/review_service.py:16` — diff отправляется во внешний LLM без удаления секретов, что нарушает `SEC-1`. Проверка: передать diff с тестовым token и убедиться, что в prompt осталось `[REDACTED]`.

### Плохой пример

Код можно улучшить. Добавьте тесты и обработку ошибок.

### Что пока неизвестно

- Точный SLA по времени ответа сервиса в целом (внешний LLM ограничен 10 с по `REL-1`).
- Требуется ли аутентификация на `/api/reviews`.

## Как использовали AI

- Для чего: собрать AS IS контекст и Context Pack из `CASE.md` и `TRAINING_PR.diff`.
- Тип промпта: zero-shot с уточнениями.
- Строка в `prompts.md`: P1-00.
- Что проверил студент: правила `SEC-1`, `API-1`, `REL-1`, `OUT-1`, `SCOPE-1`, `QA-1`, `OBS-1` перенесены из `CASE.md` без изменений; правила про `snake_case` и i18n исключены как не относящиеся к PR; примеры комментария совпадают с `CASE.md`.
