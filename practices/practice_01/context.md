## Context Pack для первого рабочего сценария

### Факты и правила

Правила репозитория, влияющие на этот PR (источник — `CASE.md`, раздел «Правила репозитория»):

- `SEC-1`: перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи. **Почему входит:** сервис отправляет diff во внешний LLM; в `TRAINING_PR.diff` функция `review` формирует prompt без санитизации.
- `API-1`: diff длиннее 20 000 символов отклоняется с HTTP 413. **Почему входит:** эндпоинт `POST /api/reviews` принимает diff без проверки размера.
- `REL-1`: внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ. **Почему входит:** в `TRAINING_PR.diff` вызов `self.llm.generate(prompt)` без `timeout` и без `try/except`.
- `OUT-1`: ответ содержит `summary`, массив `risks` и массив `checks`. В `risks` максимум три элемента с полями `file`, `line`, `evidence`, `risk`. **Почему входит:** в diff возвращается `{"comment": answer}` без требуемой структуры.
- `SCOPE-1`: сервис только советует; он не пишет код и не выполняет действия в GitHub. **Почему входит:** определяет границы того, что делает сервис; в diff нет вызовов GitHub API, но правило фиксирует запрет.
- `QA-1`: риск включается в ответ, только если он подтверждён строкой diff или правилом репозитория. **Почему входит:** задаёт критерий включения риска в ответ; в текущем коде проверка отсутствует.
- `OBS-1`: в лог пишутся только `request_id`, длительность и статус. Содержимое diff и ответа модели не логируется. **Почему входит:** новый эндпоинт будет логироваться; правило ограничивает содержимое логов.

Правила, которые не относятся к этому PR и исключены из Context Pack (источник — `CASE.md`, раздел «Эти правила не относятся к учебному PR»):

- таблицы базы данных называются в `snake_case` — в diff нет работы с БД;
- все frontend-строки проходят через i18n — в diff нет frontend.

Задача помощника:

- получает diff и возвращает краткое описание, не более трёх рисков с файлом, строкой и доказательством, список проверок;
- решение всегда принимает человек;
- помощник не может approve, merge или менять код.

### Формат входа и результата

- Вход: `TRAINING_PR.diff` (текст).
- Результат: Markdown с разделом `## Риски`, внутри которого ≤ 3 элемента, каждый — в формате `file:line — нарушение (правило). Evidence. Проверка.` Разделы отчёта: `## Краткое описание`, `## Риски`, `## Проверки`, `## Ограничения` (`OUT-1`).

### Ограничения и запрещённые действия

- Нельзя approve, merge, менять код, действовать в GitHub.
- Нельзя выдумывать строки и правила, которых нет в diff или Context Pack.
- Нельзя возвращать больше трёх рисков.
- Нельзя логировать содержимое diff и ответ модели.

### Хорошие примеры

**Для `SEC-1`:**

`app/review_service.py:16` — diff отправляется во внешний LLM без удаления секретов, что нарушает `SEC-1`. Проверка: передать diff с тестовым token и убедиться, что в prompt осталось `[REDACTED]`.

**Для `OUT-1`:**

`app/review_service.py:12` — функция `review` возвращает `{"comment": answer}` без полей `summary`, `risks`, `checks`. Нарушает `OUT-1`. Проверка: отправить `POST /api/reviews` с diff и проверить, что в ответе есть ключи `summary`, `risks`, `checks`.

**Для `API-1`:**

`app/api.py:11` — вызов `review_service.review(payload["diff"])` без проверки наличия поля `diff`. Нарушает `API-1`. Проверка: отправить `POST /api/reviews` с пустым JSON `{}`, ожидать 422, не 500.

### Плохой пример

Код можно улучшить. Добавьте тесты и обработку ошибок.

### Что пока неизвестно

- Точный SLA по времени ответа сервиса в целом. Ограничение 10 с — из правила `REL-1` в `CASE.md`, раздел «Правила репозитория»; SLA продукта — вопрос к заказчику.
- Требуется ли аутентификация на `/api/reviews`.

## Как использовали AI

- Для чего: собрать AS IS контекст и Context Pack из `CASE.md` и `TRAINING_PR.diff`.
- Тип промпта: zero-shot с уточнениями.
- Строка в `prompts.md`: P1-00.
- Что проверил студент: правила `SEC-1`, `API-1`, `REL-1`, `OUT-1`, `SCOPE-1`, `QA-1`, `OBS-1` перенесены из `CASE.md` без изменений; правила про `snake_case` и i18n исключены как не относящиеся к PR; примеры комментария совпадают с `CASE.md`.
