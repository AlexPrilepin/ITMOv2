# Few-shot

- **Артефакт Практики 1:** `practices/practice_01/context.md`, раздел «Хорошие примеры».
- **Что хотим улучшить:** в Context Pack только один пример хорошего комментария (`app/review_service.py` про `SEC-1`). Непонятно, как выглядит правильный риск для других изменённых файлов (`app/api.py`) и для других правил (`OUT-1`, `REL-1`). Few-shot даёт модели 2–3 образца — ждём, что она дополнит набор примерами в том же формате.

## Примеры

### Хороший результат

```text
app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов,
что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться,
что в prompt осталось [REDACTED].
```

Формат: `file:line` — нарушение с указанием правила → конкретная команда проверки.

### Плохой результат

```text
Код можно улучшить. Добавьте тесты и обработку ошибок.
```

Почему плохо: нет файла, строки, правила и воспроизводимой проверки.

## Запрос

```text
Ниже два примера комментариев к PR — хороший и плохой.

Хороший:
app/review_service.py:16 — diff отправляется во внешний LLM без удаления секретов,
что нарушает SEC-1. Проверка: передать diff с тестовым token и убедиться,
что в prompt осталось [REDACTED].

Плохой:
Код можно улучшить. Добавьте тесты и обработку ошибок.

Ниже — diff учебного PR. Найди в нём ещё два риска, подтверждённых правилами
SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1.
Формат каждого — как в хорошем примере: file:line — нарушение с указанием правила,
затем конкретная проверка.
```

**Приложен:** `TRAINING_PR.diff`.

## Что получили

```text
app/review_service.py:12 — функция review возвращает {"comment": answer},
нет полей summary, risks, checks. Нарушает OUT-1.
Проверка: отправить POST /api/reviews с diff, проверить, что в ответе есть
ключи summary, risks, checks.

app/api.py:11 — вызов review_service.review(payload["diff"]) без проверки
наличия поля diff. Нарушает API-1 (валидация запроса).
Проверка: отправить POST /api/reviews с пустым JSON `{}`, ожидать 422, не 500.
```

## Что изменили в исходном артефакте

- **Файл и раздел:** `practices/practice_01/context.md`, подраздел «Хорошие примеры».
- **Изменение:** один пример расширен до трёх — добавлены примеры для `app/api.py` и для правила `OUT-1`. Показано, как выглядит комментарий для разных файлов и разных правил.
- **Как проверили:** сверили оба новых комментария с `TRAINING_PR.diff` — строки 12 и 11 существуют, нарушения соответствуют правилам `OUT-1` и `API-1`.
- **Что отклонили:** предложение модели добавить абстрактный пример без `file:line` («нужно лучше обрабатывать ошибки») — не соответствует формату хорошего примера из Context Pack.
