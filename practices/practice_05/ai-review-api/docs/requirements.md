# Требования: AI-review API

Сервис получает diff pull request и возвращает отзыв помощника ревьюера.
Решение всегда принимает человек. Источник правил — `practices/practice_01/CASE.md`
учебного репозитория курса.

## Правила проекта

| Правило | Требование |
|---|---|
| `SEC-1` | Перед отправкой во внешний LLM из diff удаляются токены, пароли и приватные ключи. |
| `API-1` | Diff длиннее 20 000 символов отклоняется с HTTP 413. |
| `REL-1` | Внешний LLM-вызов имеет timeout 10 секунд; ошибка превращается в контролируемый ответ. |
| `OUT-1` | Ответ содержит `summary`, `risks` (не больше трёх) и `checks`. |
| `SCOPE-1` | Сервис только советует: не пишет код и не действует в GitHub. |
| `QA-1` | Риск попадает в ответ, только если подтверждён строкой diff или правилом. |
| `OBS-1` | В лог пишутся только `request_id`, длительность и статус; diff и ответ модели не логируются. |

## Фича A: входная валидация (`API-1`)

Эндпоинт `POST /api/reviews` принимает JSON `{"diff": "<строка>"}`.

Коды ответов совпадают с use case и E2E-сценариями практики 1
(`product_management.md`, `tests_e2e.md`).

1. Нет поля `diff` или оно не строка → HTTP 422, тело `{"error": "<причина>"}`.
2. `diff` пустой или из одних пробелов → HTTP 400, тело `{"error": "diff is empty"}`.
3. Длина `diff` больше 20 000 символов → HTTP 413, тело `{"error": "diff too large", "limit": 20000}`.
4. Ровно 20 000 символов → запрос принимается.
5. В случаях 1–3 LLM не вызывается.

## Фича B: ошибка зависимости (`REL-1`) — по желанию, в оценку ДЗ не входит

1. Ожидание ответа LLM ограничено 10 секундами; в тестах лимит можно уменьшить.
2. Timeout LLM → HTTP 504, тело `{"error": "llm_timeout"}`.
3. Любое другое исключение LLM → HTTP 502, тело `{"error": "llm_unavailable"}`.
4. В обоих случаях нет трассировки стека в ответе и нет HTTP 500.
5. Все сценарии фичи A продолжают работать.
