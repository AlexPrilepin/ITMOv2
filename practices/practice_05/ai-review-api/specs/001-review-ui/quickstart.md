# Quickstart: Review Assistant Web UI

## Что проверять в браузере (сквозные проверки)

1) Загрузка страницы
- Открыть GET /. Проверить наличие: textarea[id=diff], span[id=counter] «0/20000», кнопки id=submit, id=clear, блоки id=result и id=error.

2) Валидный запрос (P1)
- Вставить короткий unified diff. Кнопка активна. Нажать «Получить ревью». Во время запроса кнопка disabled. При 200 мок-ответе отобразить summary, не более 3 рисков (title; для diff_line — file:line и proof; для rule — rule), список checks (строки). Если secrets_masked > 0 — показать «Секреты в diff были замаскированы».

3) Ошибки (P2)
- 400: «Пустой diff…». 413: «Слишком большой diff…». 422: «Неверный запрос…». 502: «LLM недоступен…». 504: «LLM не ответил вовремя…». Сетевая ошибка: «Сетевая ошибка…».

4) Лимит (P2)
- При длине >20000 кнопка отключена; 20000 — включена. Счётчик корректно показывает N/20000.

5) Очистка (P3)
- Нажать «Очистить»: поле пусто, счётчик 0/20000, скрыт результат/ошибка.

6) Безопасность
- Проверить: нет localStorage/sessionStorage; нет логов diff/ответа в консоли; данные в DOM вставляются через textContent.

## Примечания
- Контракт: specs/review-api-contract.md (D1–D10). Сообщения об ошибках выбираются по HTTP-статусу.
- UI не меняет POST /api/reviews; добавляет только GET /.
