## Расхождения и решения

| # | Тема | Команда UI ожидала | Команда логики предложила | Решение | Почему |
|---|---|---|---|---|---|
| D1 | Риск | `{file, line, evidence: string}` | `{title, evidence: {type: diff_line, file, line, proof} \| {type: rule, rule}}` | Формат логики. UI показывает `title`; для `diff_line` — `file:line` и `proof`, для `rule` — метку правила. | QA-1 допускает подтверждение правилом — у такого риска нет файла и строки. |
| D2 | `checks` | объекты `{name, status: pass/warn/fail, details}` | массив строк | Массив строк. UI убирает цветные статусы (FR-012). | Сервис советует, а не исполняет проверки (SCOPE-1); статус pass/fail был бы выдуман моделью (QA-1). |
| D3 | Признак маскирования | `redactionsApplied: boolean`, `maskedCount?` | нет поля | Новое поле `secrets_masked: integer` (≥ 0) — число замен на `[SECRET]`. UI показывает отметку, если > 0. | Логика и так считает замены; одно поле закрывает оба вопроса UI. Значения секретов не раскрываются. |
| D4 | Тело ошибок | `{code, message, details?}` | без изменений | Без изменений: `{"error": "<код>"}`, у 413 ещё `"limit": 20000`. UI выбирает сообщение по HTTP-статусу, а не по телу. | Фичи A и B и их тесты не меняем (FR-008 логики, конституция I). |
| D5 | Нумерация `line` | 1-based, новая версия файла | открытый вопрос (FR-009) | 1-based номер строки в **новой** версии файла (правая сторона hunk). Ссылаться через `diff_line` можно только на добавленные и контекстные строки; риск про удалённую строку подтверждается правилом. | Однозначно вычисляется из заголовка hunk `+c,d`; совпадает с ожиданием UI. |
| D6 | Отбор до трёх рисков | UI показывает первые 3 | открытый вопрос (FR-010) | Сохраняется порядок модели после отбрасывания неподтверждённых; поля severity в контракте нет. | Простота (конституция V); UI ничего не пересортировывает. |
| D7 | Секреты в `proof` | сервер обязан маскировать | подтверждение по **исходному** diff | `proof` сверяется с **замаскированным** diff и возвращается из него — в ответе только `[SECRET]`, не значения. | Иначе секрет из исходного diff попадёт в ответ API и на страницу (нарушение SEC-1 через обходной путь). |
| D8 | Пустая сводка | — | открытый вопрос (FR-011) | `"summary": "review summary unavailable"`, если модель вернула пустой текст. | Нужна непустая строка (SC-002 логики); английский — как у кодов ошибок. |
| D9 | Метаданные | `requestId`, `model`, `elapsedMs` | нет | Не входят в ответ. | OBS-1 решается логом (change `request-observability`), UI они не нужны. |
| D10 | Совместимость | — | `{"comment"}` уходит | Поле `comment` удаляется. Тесты с ожиданием `comment` (`test_api.py`, `test_feature_b.py` — успешный сценарий) обновляются под новый контракт; это не ослабление, а смена контракта решением человека. Принятая спецификация OpenSpec `llm-dependency-errors` (сценарий «200 `{"comment"}`») устаревает в части формата успеха. | Принцип VI: изменение контракта обновляет обе спеки и тесты. |

## Контракт

### `GET /`

200, `text/html; charset=utf-8` — страница UI. Тот же FastAPI-процесс, same-origin.

### `POST /api/reviews`

Запрос: `Content-Type: application/json`, тело `{"diff": "<строка>"}`. Прочие поля игнорируются.

**200**:

```json
{
  "summary": "string, непустая",
  "risks": [
    {
      "title": "string",
      "evidence": {"type": "diff_line", "file": "app/config.py", "line": 42, "proof": "API_TOKEN = [SECRET]"}
    },
    {
      "title": "string",
      "evidence": {"type": "rule", "rule": "OBS-1"}
    }
  ],
  "checks": ["string"],
  "secrets_masked": 1
}
```

- `risks`: 0–3 элемента; `evidence.rule` ∈ {SEC-1, API-1, REL-1, OUT-1, SCOPE-1, QA-1, OBS-1}.
- `proof` — подстрока строки `line` замаскированного diff.
- Неразборчивый ответ модели → 200, `summary` = первые 300 символов ответа, `risks: []`, `checks: []`.

**Ошибки** (без изменений):

| Код | Тело | Когда | Сообщение UI |
|---|---|---|---|
| 400 | `{"error": "diff is empty"}` | пустой или пробельный diff | «Пустой diff. Вставьте содержимое diff и повторите попытку.» |
| 413 | `{"error": "diff too large", "limit": 20000}` | > 20 000 символов | «Слишком большой diff. Лимит — 20 000 символов.» |
| 422 | `{"error": "<причина>"}` | нет `diff` или не строка | «Неверный запрос. Проверьте формат diff.» |
| 502 | `{"error": "llm_unavailable"}` | ошибка LLM | «LLM недоступен…» + подсказка о ручном ревью |
| 504 | `{"error": "llm_timeout"}` | timeout LLM (10 с) | «LLM не ответил вовремя…» + подсказка о ручном ревью |
| — | — | сеть / прочие 5xx | «Сетевая ошибка…» / «Внутренняя ошибка сервиса…» |

### Состояния UI ↔ ответы API

`idle` → `editing` → `loading` (одна заявка, кнопка заблокирована) → `success` (200) | `error` (400/413/422/502/504/сеть) → «Очистить» → `idle`.
