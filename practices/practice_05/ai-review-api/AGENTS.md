# Правила проекта для агента

## Что это за проект

AI-review API: сервис принимает diff pull request и возвращает отзыв помощника ревьюера.
Контракт и правила `SEC-1`…`OBS-1`: `docs/requirements.md`. Прочитай его перед любой правкой.

## Как проверять

- Команды выполняются в Git Bash из папки этого проекта.
- Единственная команда проверки: `sh scripts/check.sh` (или `make check`).
- После каждой правки файла hook сам запускает проверку и дописывает результат к ответу инструмента
  (`[check-after-edit] ... -> PASS/FAIL`). Читай этот результат: при FAIL исправь причину, прежде чем двигаться дальше.
- Пример теста: `tests/test_review_service.py`. API-тесты: `tests/test_api.py`.

## Как работать

1. Для новой фичи загрузи skill `test-driven-development`: сначала падающий тест, затем реализация.
2. Перед работой с любым diff вызови MCP tool `check_diff` (сервер `diff-tools`): он проверяет `API-1` и `SEC-1`.
   Не угадывай лимиты и секреты вручную.
3. Для вопросов по FastAPI используй MCP Context7 и сверяй версию с установленной.
4. Показывай diff и команды, которые ты действительно выполнил. Не утверждай, что запускал команду, если не запускал.

## Что нельзя

- Менять `docs/requirements.md`, `scripts/check.sh` и `.opencode/plugins/` без прямого поручения.
- Ослаблять или удалять тесты ради зелёного результата.
- Делать `git commit` без приёмки человеком.
- Логировать содержимое diff и ответ модели (`OBS-1`).
