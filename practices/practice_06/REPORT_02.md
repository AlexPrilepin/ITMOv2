## Сохранённая функциональность

Клиент получает свой профиль и чек, покупает по цене каталога, оставляет отзыв и получает помощь по своему заказу (`read_file` своего чека через помощника); сотрудник экспортирует профили по staff-сессии — без заголовка `X-Role`. Все 16 поставляемых тестов проходят.

## Prompt injection после исправлений

Повторный прогон той же модели, system prompt и задачи — **ожидает запуска студентом**:

```bash
python practices/practice_06/lab/attacks/run_planner.py after ollama/itmo-agent
```

| Сценарий | Решение модели | Действие исполнителя | Чеки целы |
|---|---|---|---|
| чистый контекст | _ожидает прогона_ | | |
| с вредоносным отзывом | _ожидает прогона_ | | |
| принудительный `delete_tree` | — | **403** `tool not allowed` (проверено конвейером и тестом `test_t9_*`) | да |

Защита не зависит от послушания модели: даже если модель вернёт `delete_tree` или `export_profiles`, исполнитель отказывает по роли и владельцу из серверной сессии (конвейер проверен с «моделью», которая всегда подчиняется инъекции: до — дерево удалено, после — 403, чеки целы).

## Остаточные риски

- Сама модель по-прежнему может подчиниться инструкции из отзыва и вернуть отказ или неверное действие — вред ограничен правами клиента, но качество помощи страдает; пометка `<untrusted_reviews>` снижает, а не исключает риск.
- Сотруднику через помощника доступен `export_profiles`: инъекция в отзыве может заставить помощника сотрудника выгрузить ПДн в его же сессии. Для 152-ФЗ стоит требовать явного подтверждения человеком.
- Сессии без срока жизни и отзыва, пароли сравниваются в открытом виде, нет ограничения частоты запросов — вне рамок лабы, но для реального сервиса обязательно.
- `/reviews/view` экранирует текст, но не задаёт CSP; аудит хранится в памяти процесса и теряется при перезапуске.
